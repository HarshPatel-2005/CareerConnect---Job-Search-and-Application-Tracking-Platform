# Sprint 3 Plan

## Overview

This document outlines the plan for Sprint 3 of the project. It includes the objectives, and deliverables for the sprint, as well as the responsibilities of each team member.

## Objectives

The goal of sprint 3 is to continue on the work started in sprint 2 by adding new features and improving test coverage.

The specific new features to be added in this sprint include:

1. Recruiter Dashboard and Posting Management:
   - Allow recruiters to create and manage job postings.
   - Allow recruiters to view applications received for a posting.
   - Allow recruiters to update the status of applications.
2. Application Analytics & History Dashboard
   - Display job seeker application history
   - Display job seeker application status
   - Display job seeker job search metrics
3. Notifications & Reminders
   - Notify users of application updates (status changes, interview invites, etc.)
   - Remind users of upcoming interviews and application deadlines
4. AI Feature (start in Sprint 3, complete in Sprint 4)
   - Create a resume parser that extracts structured information from uploaded resumes and stores it in the database and profile.
   - Create an AI powered resume/job matching feedback feature that allows users to get feedback on their resume and how well it matches a specific job posting.
   - Ensure that the AI feature is accurate and does not hallucinate any skills or experience.

## Deliverables

The deliverables for Sprint 3 include:

- This document (Sprint 3 Plan)
- User stories for the new features (with tasks and acceptance criteria)
- At least 1 acceptance test for each user story
- Sprint 3 feature implementation
- AI Usage Logs
- Project board and backlog
- Create unit tests for all sprint 3 features
- Maintain the CI pipeline to automatically run new tests
- Meeting minutes
- Contribution logs (per team member)
- One page summary report (per team member) of the work completed in Sprint 3

## Work Breakdown

The work for Sprint 3 will be broken down as follows:

Each team member will be assigned a specific feature (see above) to implement. They will be responsible for writing the code, creating tests, and ensuring that their feature meets the acceptance criteria.
